## 6. Method and limits

- Parser: `tools/unity_yaml.py`, stdlib only. Unity's `!u!<class>` tags break strict YAML loaders, so documents are split on `--- !u!` and parsed with an indentation-aware line reader that also rejoins Unity's wrapped inline maps (`{fileID: 1, guid: x,\n    type: 3}`).
- `hierarchyActive` is computed by walking `Transform.m_Father` -> `Transform.m_GameObject` to the root and AND-ing every `m_IsActive`. If any ancestor is a `stripped` prefab member its state is not in `main.unity` and the value is reported as `unknown`.
- Culling-mask layer names come from `ProjectSettings/TagManager.asset`; unnamed indices print as `layerN`.
- `m_TargetTexture` guids are resolved through `Assets/**/*.renderTexture.meta`, and the `.renderTexture` is read for width/height/AA.
- Cameras living inside prefab assets (e.g. an OVR rig) cannot have their component fields measured from the scene file; they are listed as *name only*.
- Lights are measured in two places: the 13 `!u!108` documents in `main.unity`, plus the Lights inside each `!u!1001` PrefabInstance's source `.prefab` (resolved through the instance's `m_Modification` overrides, as Unity does at load). Only the first group can be changed by editing the scene file.
- Every `!u!114` in the scene has its `m_Script` guid resolved and grepped, so the "another script could re-enable it" risk is measured (section 4.6) rather than assumed. Scripts with a capability but no `Awake`/`Start`/`Update`/`OnEnable` are reported as editor-only.
- Not measured here: actual GPU cost / draw-call counts (needs a device profile, card N1), whether an AnimationClip or Animator toggles these objects, and scripts that are not components in this scene (e.g. anything added via `AddComponent` at runtime from an asset bundle). Cameras inside prefab assets would also be name-only; none were found.
